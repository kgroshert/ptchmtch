# Glide Exercise Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a free-pace **Glide** exercise (low note → up a third or fifth → back down, no pause) to the
Support page, next to Messa di voce. It judges even pitch movement and steady volume, and has its own
History tab.

**Architecture:**
- The Support page keeps one host class, `SupportTrainer`, in `src/support.ts`. It owns everything
  shared: voice, note stepping, the round phases, the breathe-in floor, mic samples, canvas set-up,
  traces and the result panel.
- Each exercise implements a small `SupportExercise` interface: `MessaExercise` in `src/messa.ts` and
  `GlideExercise` in `src/glide.ts`. The interface covers the notes played, cues, analysis, drawing of
  its own lanes and marks, result items, stats and the session row.
- Shared pure analysis helpers move to `src/support-analysis.ts`.
- Pure analysis functions (`analyseMessa`, `analyseGlide`) are checked offline with tsx scripts.

**Tech Stack:** Vite + TypeScript (no framework), Web Audio, canvas, localStorage. tsx for the offline
check scripts.

**Spec:** `docs/superpowers/specs/2026-11-14-glide-design.md`

## Global Constraints

- **No commits.** The user commits only when they ask. Every task ends with a checkpoint (type check and
  checks pass), not a commit.
- **Messa di voce must not change** in behaviour or scoring. `npm run check` (the messa baseline) must
  pass after every task.
- **No new page and no new menu item.** Everything lives in `section#support`.
- **Free pace.** Speed is never judged. Up and down times are information only.
- **Evenness is measured on pitch smoothed over about 0.25 s**, so vibrato doesn't count as unevenness.
- **Intervals:** Third = 4 semitones (the default) and Fifth = 7 semitones. Every glide starts on the
  low note.
- **Default low note:** `round((v.low + v.high) / 2 − interval / 2) + glideOffset`. Both the low and the
  top note must stay inside `VOICES` `low..high`.
- **Shared voice:** one voice setting for both exercises. Changing it resets both offsets to 0.
- **Prefs** stay under the existing key `"ptchmtch.messa"`, extended with these fields:
  `exercise: "messa" | "glide"` (default `"messa"`), `interval: 4 | 7` (default 4) and
  `glideOffset: number` (default 0). Existing saved prefs must still load.
- **Glide history:** key `"ptchmtch.glide.sessions"`, History tab id `"glide"`, label `Glides`.
- **Starting thresholds** (constants in `src/glide.ts`):
  - `DRIFT_CENTS = 30`
  - `STALL_FRACTION = 0.25`
  - `STALL_SECONDS = 0.5`
  - `JUMP_CENTS = 60` within `JUMP_SECONDS = 0.1`
  - `TOP_HOLD_SECONDS = 1`
  - `PITCH_SMOOTH_SECONDS = 0.25`
  - Sags and surges: `BUMP_DB` (3 dB), lasting at least `SAG_SECONDS = 0.3`.
  - Ignore the onset (first 0.3 s) and the release (last 0.4 s).
- **Glide round:**
  - Start plays low, then top, 1.2 s each.
  - Hear plays low, top, low, 1 s each.
  - Breathe-in lasts 1.5 s.
  - The round finishes after 1 s of silence once there has been at least 2 s of voice, or after a
    60 s cap.
- **Graph:**
  - The glide pitch lane spans `−100¢ … interval·100 + 100¢` from the low note. It marks the low and top
    notes, with fainter lines for the major-scale notes in between, and a tolerance band around low
    and top.
  - The time axis is `max(25, last t + 1)` seconds.

## Review Focus

These are the conditions a real singer will hit that the obvious tests miss. Each one is pinned by a
named case in `scripts/check-glide.ts` (Task 3) or a browser check (Task 5).

1. **A naturally rounded turn and slowing into it.** No stall and no middle drift should be flagged. The
   singer decelerates for about 0.4 s around the top. Test: `rounded turn`.
2. **A short scoop up into the first note.** The singer starts 50¢ under it for 0.3 s. That should give
   no drift, stall or start error beyond tolerance. Test: `onset scoop`.
3. **Volume that rises gently with pitch,** about +2 dB at the top. That is not a sag or a surge.
   Test: `volume follows pitch`.
4. **An incomplete glide.** The singer only goes up and stops, or holds one note without gliding. There
   should be no crash, `down` (or both legs) should be null, and the UI should say what was missing.
   Tests: `up only`, `no glide`.
5. **A pitch-tracker octave slip mid-glide** (+1200¢ for 0.2 s). It should be reported once, as a
   crack, with no separate jump at the same moment. Test: `octave slip`.

```ts
export interface GlideLeg {
  from: number; to: number;          // seconds
  c0: number; c1: number;            // smoothed cents at the leg's endpoints (from the low note)
  rms: number;                       // RMS deviation from the straight line, cents
  worst: { t: number; dev: number; near: number; middle: boolean } | null; // signed dev; near = MIDI; middle = in the middle 60% of the leg
  stalls: { t: number; near: number }[];
  jumps: { t: number; near: number }[];
}
export interface GlideResult {
  from: number; to: number;          // voiced span
  startCents: number;                // vs the low note
  topCents: number;                  // the highest smoothed pitch minus interval·100 (+ overshoot, − undershoot)
  endCents: number | null;           // vs the low note; null when there was no down leg
  hold: { from: number; to: number } | null; // set when the pitch stayed at the top ≥ TOP_HOLD_SECONDS
  up: GlideLeg | null;               // null when there was no glide (top < 50% of the interval)
  down: GlideLeg | null;             // null when it never came down by at least 50% of the interval
  levelDb: number; volumeDev: number;          // median dB and RMS around it, edges excluded
  bumps: { t: number; kind: "sag" | "surge"; db: number; near: number }[];
  lost: { t: number; reason: LostReason } | null;
  vibrato: Vibrato | null;           // info only
  smoothCents: (number | null)[];    // per frame, for drawing the reference lines and marks
  smooth: number[];                  // smoothed dB per frame
}
export function analyseGlide(frames: SupportFrame[], floorDb: number, interval: number, lowMidi: number): GlideResult | null;
```

Algorithm decisions that the types don't fix:
- The **turn** is the point of highest smoothed pitch. The **hold** is the contiguous run within 25¢ of
  that maximum around the turn. When the hold lasts at least `TOP_HOLD_SECONDS`, `up` ends at the start
  of the hold and `down` begins at its end. Otherwise both legs meet at the turn.
- The **start** is the first frame after the 0.3 s onset whose smoothed pitch is within 60¢ of 0. If no
  frame qualifies, the start is the first frame after the onset. The **end** is the last pitched frame
  before the 0.4 s release.
- **Stalls and jumps** are not searched for within 0.5 s of a leg's ends.
  - A **stall**: the speed over a 0.25 s window, in the leg's direction, is below
    `STALL_FRACTION × |c1 − c0| / (to − from)` for at least `STALL_SECONDS`.
  - A **jump**: the raw pitch moves more than `JUMP_CENTS` within `JUMP_SECONDS`.
  - Jumps inside a reported crack's 0.3 s window are dropped.
- **Lost control:** `findLost` is called with `expected` = the leg's straight line at that time.
- **Middle:** `t` lies within the middle 60% of the leg's time.
